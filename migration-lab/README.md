# migration-lab（AWS のラボ）

## 始める前に

このラボの制限時間は60分です。時間切れになると作成したリソースは消え、続きからは再開できません。
時間内に終わらなくても構いません。答え合わせ用の動画を見て流れをつかめば、やり直しは何度でもできます。
リージョンは米国東部（バージニア北部）us-east-1 のまま操作してください。

- ラボは、レクチャーの動画の再生中に「演習」を押すと始まります。
- やり直した直後は「Your lab environment is still cleaning up from a previous session」と出ることがあります。「ワークスペースを再起動」を何度も押さず、5分ほど待ってから開き直してください。
- やり直したときに「別のアカウントでログインするにはログアウトする必要があります」と出たら、ログアウトしてから、ラボの画面で AWS コンソールを開き直してください。
- 手順の中で名前を入れる欄は、すべてこの README の値を使ってください。

番号は課題の番号です。

## 課題1: DynamoDB のテーブルを作る

DynamoDB →「テーブルの作成」で、次の値を入れます。

| 項目 | 値 |
|---|---|
| テーブル名 | `ExpenseReports` |
| パーティションキー | `reportId`（文字列） |
| ソートキー | 入れない |

それ以外は既定のまま「テーブルの作成」を押します。状態が「作成中」から「アクティブ」に変わるまで待ってから、次の課題に進みます。

## 課題2: Lambda 関数を作る

1. jar をダウンロードする

課題2の欄にある `expense-report-lambda.jar` を右クリックし、「名前を付けてリンク先を保存」で保存します。左クリックするとラボの画面を離れる確認が出るので、押さないでください。保存したファイル名が `.jar` で終わっているか確かめます（Mac では付かないことがあります）。

2. 関数を作成する

Lambda →「関数の作成」→「一から作成」を選び、次の値を入れて「関数の作成」を押します。

| 項目 | 値 |
|---|---|
| 関数名 | `expense-report-lambda` |
| ランタイム | Java 21 |
| アーキテクチャ | x86_64（既定のまま） |
| 実行ロール | 既定のまま（基本的な Lambda アクセス権限で新しいロールを作成） |

3. 作成後に設定する

作成すると関数の画面が開きます。次の4つを、上から順に設定します。

| 場所 | 項目 | 値 |
|---|---|---|
| 「コード」タブ →「更新 ▼」→「.zip または .jar ファイル」 | jar | 1 で保存した `expense-report-lambda.jar` |
| 「コード」タブの下の「ランタイム設定」→「編集」 | ハンドラ | `com.example.expensereport.lambda.ExpenseReportLambdaHandler::handleRequest` |
| 「設定」タブ →「環境変数」→「編集」 | キー / 値 | `TABLE_NAME` / `ExpenseReports` |
| 「設定」タブ →「一般設定」→「編集」 | タイムアウト | 30秒 |

ハンドラは「ランタイム設定」の「編集」で入れます。同じ欄の「ランタイム管理設定を編集」は別の設定です。

## 課題3: API Gateway で HTTP API を作る

1. API を作成する

API Gateway →「HTTP API」の「構築」で、次の値を入れます。

| 項目 | 値 |
|---|---|
| 統合 | Lambda（リージョン us-east-1、関数 `expense-report-lambda`） |
| バージョン | 2.0（必ずこのまま。1.0 では動きません） |
| API 名 | `expense-report-http-api` |
| IP アドレスのタイプ | IPv4（既定のまま） |

「次へ」を押してルートを設定します。

| 項目 | 値 |
|---|---|
| メソッド | `ANY` |
| リソースパス | `/{proxy+}`（最初から入っている `/` は消してから入力） |
| 統合ターゲット | `expense-report-lambda` |

「次へ」を押し、ステージは `$default` のまま「次へ」、最後に「作成」を押します。作成後に出る「デプロイ」は押さなくて構いません（`$default` は自動でデプロイされます）。

2. エンドポイントを開く

左のメニューの「デプロイ」→「ステージ」→「$default」を開き、「URL を呼び出す」に出ている URL の末尾に次のパスを付けて、ブラウザで開きます。この URL を、以降の課題では「エンドポイント」と呼びます。

```
/api/reports
```

`{"message":"Internal server error","cause":"DynamoDbException"}` と表示されれば、500 が返っています。

状態コードの 500 を自分の目で確かめたいときは、ブラウザの開発者ツール（Windows は F12、Mac は Option + Command + I）の「ネットワーク」タブを開いてからページを再読み込みし、`reports` の行の「ステータス」が 500 になっていることを見ます。

## 課題4: ログで原因を探す

Lambda の関数の画面 →「モニタリング」タブ →「CloudWatch ログを表示」を押します。一覧の一番上（最新）のログストリームを開き、検索ボックスに次の語を入れて絞り込みます。

```
not authorized
```

## 課題5: 実行ロールに権限を足す

1. 実行ロールを開く

Lambda の関数の画面 →「設定」タブ →「アクセス権限」の「実行ロール」にあるロール名（`expense-report-lambda-role-` で始まるリンク）を押します。IAM の画面が開きます。「編集」は押しません。

2. 広い権限で動くことを確かめる

「許可を追加」→「ポリシーをアタッチ」で `AmazonDynamoDBFullAccess` を検索してチェックを入れ、「許可を追加」を押します。エンドポイントを開き直し、`[]` が返ることを確かめます。

3. 必要な権限だけに絞る

「許可を追加」→「インラインポリシーを作成」→「JSON」タブに、次の JSON を貼り付けます。

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["dynamodb:Scan", "dynamodb:GetItem", "dynamodb:PutItem"],
      "Resource": "arn:aws:dynamodb:us-east-1:*:table/ExpenseReports"
    }
  ]
}
```

ポリシー名は次の値にして作成します。

```
ExpenseReportsLabAccess
```

最後に `AmazonDynamoDBFullAccess` にチェックを入れて「削除」を押し、外します。エンドポイントを開き直して `[]` が返れば完了です。

## 課題6: サンプルデータを入れる

1. Lambda の関数 `expense-report-lambda` の画面に戻ります。
2. 「コード」タブの下の「ランタイム設定」→「編集」で、ハンドラを次の値に変えて保存します。

```
com.example.expensereport.lambda.SeedLambdaHandler::handleRequest
```

3. 「テスト」タブで、次の値を入れて「テスト」を押します。

| 項目 | 値 |
|---|---|
| イベント名 | `seed25` |
| イベント JSON | `{"reports": 25}` |

4. 成功したら、ハンドラを課題2の値に戻して保存します。

```
com.example.expensereport.lambda.ExpenseReportLambdaHandler::handleRequest
```

5. エンドポイントを開き直し、25件の申請が返ることを確かめます。

## 課題7: CloudWatch で Scan の回数を数える

1. CloudWatch → 左のメニューの「メトリクス」→「すべてのメトリクス」で、「DynamoDB」を押します（「自動ダッシュボードを表示」ではありません）。
2. 「テーブル操作メトリクス」を選び、次の行にだけチェックを入れます。Scan の行は2つありますが、メトリクス名で選びます。

| 項目 | 値 |
|---|---|
| テーブル名 | `ExpenseReports` |
| Operation | `Scan` |
| メトリクス名 | `SuccessfulRequestLatency` |

3. 「グラフ化したメトリクス」タブで、その行の統計と期間を変えます。

| 項目 | 値 |
|---|---|
| 統計 | サンプル数 |
| 期間 | 1分 |

4. グラフの上の時間の範囲を「1時間」にします。
5. エンドポイントを1回だけ開き、1〜2分待ってから、グラフの一番右の点にマウスを乗せます。値が Scan を呼んだ回数です。それより前の点は、課題5〜6でエンドポイントを開いたぶんです。
